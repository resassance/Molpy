## О проекте

Molpy строится вокруг музыкальной записи: название, исполнители, релиз, обложка и версия трека. Ответы источников преобразуются в общую модель `Track`, чтобы интерфейс не зависел от структуры YouTube API.

Первый этап — Android. Затем планируются Windows и Linux, позднее рассматривается web. iOS в текущие планы не входит. Наличие общих Kotlin-модулей ещё не означает готовность приложения для desktop или браузера.

Собственный аккаунт Molpy и сервер не требуются. Вход в Google не реализован. Проект независим от YouTube, Google и поставщиков текстов; обход DRM и платного доступа не предусмотрен.

## Что реализовано

Здесь перечислена реализация текущего технического прототипа. Её готовность к реальному использованию ещё требует проверки на устройстве.

| Возможность | Текущее состояние |
| --- | --- |
| Поиск музыки | Каталог YouTube Music через InnerTubeX; нормализация результатов в `Track`, метаданные и обложки |
| Подготовка воспроизведения | Отдельный YouTube resolver на InnerTubeX 0.10.0; временный адрес потока получается при выборе записи |
| Android-аудио | Media3 ExoPlayer и `MediaSessionService`; запуск, пауза, продолжение, перемотка, позиция и длительность |
| Системная интеграция | Сервис воспроизведения, media session и системные элементы управления |
| Тексты песен | Загрузка при открытии текста: обычный текст из YouTube Music, обычный и синхронизированный текст из LRCLIB при наличии |
| Ошибки и смена трека | Нормализованные ошибки и защита от подмены текущего состояния запоздавшими ответами |

Текст может отсутствовать, а доступные синхронизированные строки могут требовать проверки на слух. Ошибка загрузки текста не должна останавливать аудио.

## Ограничения и планы

- **Сеть:** сейчас используется системное соединение. Там, где YouTube недоступен напрямую, нужен работающий системный VPN. Встроенные HTTP/SOCKS5 proxy ещё не реализованы.
- **Воспроизведение:** поддержаны потоки PROGRESSIVE/HLS; полная запись и совместимость конкретных живых источников пока не подтверждены. Изменения upstream могут нарушить поиск или получение потока.
- **Хранение:** нет скачиваний, офлайн-воспроизведения, постоянной медиатеки и восстановления после завершения процесса. Room/SQLite предусмотрены для следующего этапа.
- **Очередь:** полноценная пользовательская очередь, избранное и история пока не реализованы.
- **Интерфейс:** текущий экран служит инженерной проверке. Финальный UX и оформление будут выбраны после проверки основной цепочки.

Ближайший шаг — проверить поиск, правильность записи и обложки, полное воспроизведение, управление и тексты на Android. Далее — настройки сети, постоянное хранение, очередь и явные офлайн-загрузки. Desktop и web относятся к более поздним этапам.

Подробные цели и границы описаны в [спецификации](docs/superpowers/specs/2026-10-17-music-player-design.md). Спецификация включает будущие возможности и не является перечнем готовых функций.

## Установка и первый запуск

**Требования:** Android 6.0 / API 23 или новее, 64-битное устройство `arm64-v8a` либо эмулятор/устройство `x86_64`. 32-битные ABI не включены в APK.

1. Откройте [релиз v0.1.0-alpha.1](https://github.com/resassance/Molpy/releases/tag/v0.1.0-alpha.1) и скачайте `Molpy-v0.1.0-alpha.1-debug.apk`.
2. Установите APK, разрешив установку из выбранного источника в настройках Android, если система запросит это.
3. Проверьте системное подключение. Если YouTube в вашей сети недоступен, включите системный VPN до запуска проверки.
4. Откройте Molpy, введите исполнителя и название, нажмите «Найти» и выберите запись.
5. Проверьте звук, паузу, продолжение и перемотку. Откройте «Текст песни» для загрузки доступного текста.

Это **debug APK для валидации**, а не готовый стабильный релиз. Успешная установка, найденный трек или движущийся таймер сами по себе не доказывают воспроизведение полной песни. Для воспроизводимой проверки используйте [процедуру на устройстве](docs/validation/core-playback.md).

## Сборка из исходников

Нужны:

- JDK 17, доступный через `JAVA_HOME`;
- Android SDK Platform **37** и Build Tools **36.0.0**;
- путь к Android SDK через `ANDROID_HOME` или `sdk.dir` в локальном `local.properties`;
- сетевой доступ к Gradle distributions, Google Maven, Maven Central, Gradle Plugin Portal и JitPack для получения инструментов и зависимостей.

Версии библиотек закреплены в [version catalog](gradle/libs.versions.toml); Gradle Wrapper включён в репозиторий.

```sh
git clone https://github.com/resassance/Molpy.git
cd Molpy
./gradlew projectCheck
./gradlew :androidApp:assembleDebug
```

В Windows используйте Gradle Wrapper для Windows:

```powershell
.\gradlew.bat projectCheck
.\gradlew.bat :androidApp:assembleDebug
```

Готовый локальный APK: `androidApp/build/outputs/apk/debug/androidApp-debug.apk`.

`projectCheck` запускает тесты `core` и `shared`, компиляцию общих модулей для JVM/desktop, Android unit tests, lint и сборку debug APK. Для этих тестов не требуется доступ к живым музыкальным источникам; зависимости при первой сборке всё равно нужно скачать.

## Архитектура и стек

| Модуль | Ответственность |
| --- | --- |
| [`core`](core) | Модели, идентичность треков, контракты источников, поиск и сопоставление, координация воспроизведения и текстов |
| [`shared`](shared) | Адаптеры каталога, resolver и текстов, HTTP, загрузка обложек, общее состояние и технический Compose UI |
| [`androidApp`](androidApp) | Android entry point, Media3 engine, media session и сервис воспроизведения |

Идентичность и происхождение записи отделены от идентификатора воспроизведения. Подписанный URL потока — временное значение в памяти процесса, а не постоянный идентификатор трека или сохраняемая ссылка.

| Назначение | Технология |
| --- | --- |
| Общая логика и UI | Kotlin 2.4.21, Compose Multiplatform 1.12.2, coroutines и Flow |
| Каталог и resolver | InnerTubeX 0.10.0 |
| HTTP | Ktor 3.6.0 с OkHttp; Media3 OkHttp data source |
| Android-аудио | Media3 1.11.1 |
| Обложки | Coil 3.6.3 |
| Тексты | YouTube Music и [LRCLIB](https://lrclib.net/) |
| Постоянные данные — запланировано | Room / SQLite; зависимости добавлены, пользовательское хранилище ещё не реализовано |

## Проверки и статус доказательств

Текущий набор содержит **160 прошедших офлайн-тестов**. Они проверяют нормализацию и идентичность записей, границы адаптеров, выбор и разбор текстов, управление состоянием и воспроизведением. Это полезная проверка логики, но не доказательство доступности каталога или полного аудио в конкретной сети.

**Пока не подтверждены:** выполнение на реальном Android-устройстве, работа собственной цепочки с живыми музыкальными источниками, полное прослушивание от начала до естественного конца и точность синхронизации текста на слух.

[Процедура проверки](docs/validation/core-playback.md) описывает выбор записей, проверку метаданных и обложек, полный прогон, pause/resume/seek, фон, пересоздание экрана и тексты. Инструментальные проверки с синтетическим аудио учитываются отдельно от живого воспроизведения.

## Участие в разработке

Ошибки и предложения принимаются через [GitHub Issues](https://github.com/resassance/Molpy/issues). Для ошибки укажите:

- версию релиза, модель устройства, Android/API и ABI;
- режим сети и включён ли системный VPN, без его реквизитов;
- шаги, ожидаемый и фактический результат, отображённый код ошибки;
- при необходимости — запрос, исполнителя, название, версию записи и стабильный ID источника.

Не публикуйте токены, cookies, пароли proxy/VPN, подписанные media URL и сырые ответы источников. Для диагностики не нужны копии аудио или полные тексты песен.

Перед pull request опишите изменение и выполните `projectCheck`. Для изменений resolver или player отдельно укажите, что проверено на устройстве, а что покрыто только тестами.
